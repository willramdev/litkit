<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner -> GitHub Pages environment | The `deploy` job authenticates to the `github-pages` environment via the OIDC `id-token` (built-in `GITHUB_TOKEN`, no PAT) |
| docs.yml token scope -> repository | The `build` job holds `contents: read` only; `pages: write` + `id-token: write` are the sole write scopes, isolated from `ci.yml`/`release.yml` |
| third-party actions -> workflow | Every step uses a first-party `actions/*` action pinned to a current major |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-8-04 | Elevation of Privilege | `docs.yml` workflow token | high | mitigate | Top-level `permissions` is exactly `contents: read` + `pages: write` + `id-token: write`; the sibling workflows' scopes are proven untouched by `git diff --exit-code -- ci.yml release.yml` |
| T-8-05 | Tampering | third-party GitHub Actions (supply-chain) | high | mitigate | First-party `actions/*` only, pinned majors (checkout@v4, setup-node@v4, configure-pages@v6, upload-pages-artifact@v5, deploy-pages@v5); Phase 12 adds SHA-pinning + Dependabot |
| T-8-06 | Tampering | concurrent Pages deploys racing | medium | mitigate | `concurrency: {group: pages, cancel-in-progress: false}` serializes deploys and never cancels an in-flight publish |
| T-8-07 | Tampering | docs build job mutating the repo | medium | mitigate | The `build` job holds `contents: read` only and never pushes; its output is an uploaded Pages artifact, not a commit |
| T-8-SC | Tampering | npm/package installs in this plan | n/a | accept | None — this plan adds no dependency (`npm ci` installs the already-audited lockfile; `typedoc` legitimacy is covered by Plan 08-01) |
</threat_model>
