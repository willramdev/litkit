<objective>
Complete the phase by expanding CEM to `@willramdev/router` — the hardest of the three packages. Its three elements (`router-outlet`, `router-provider`, `router-link`) register through the idempotent `define(tag, ctor)` wrapper, which the analyzer cannot statically resolve, so each class needs a JSDoc `@tag <name>` to populate `tagName` (the hollow-manifest fix, PITFALLS §5 / D-11). Router also carries the fullest demo/example exclude set and builds via `node scripts/build.js` rather than `vite build`.

Purpose: this is where the phase's core completeness risk lives. `forms` (09-01) and `query` (09-02) proved the pattern on real-decorator elements; router adds the `define()`-wrapper `@tag` mechanism, the richest enriched JSDoc (`router-error` event, `managefocus` attribute), and the largest exclude set. The tag-set equality gate is the built-in verifier — if `@tag` fails to populate `tagName`, the router tags are absent from the extracted set and the gate fails, prompting the `@tag`→`@tagname` fallback.
Output: a green router manifest (`tagName` == `{router-outlet, router-provider, router-link}`) + VS Code custom-data + web-types shipped in the tarball; the full three-package CEM gate green.
</objective>
