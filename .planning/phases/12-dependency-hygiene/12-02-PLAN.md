<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| push / pull_request event -> ci.yml | Untrusted PR contents run under a read-only token; no scope creep allowed |
| push to main -> release.yml | Auth-bearing publish; highest blast radius (SHA-pinned action + write scopes) |
| public npm advisory endpoint -> audit step | Audit POSTs the dependency tree out; needs no token, returns advisory data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-03 | Elevation of Privilege | ci.yml token scope | high | mitigate | Audit needs only `contents: read`; no `security-events` write scope added (OSV+SARIF rejected precisely to avoid it) — the top-level token is unchanged (D-01/D-04) |
| T-12-05 | Information Disclosure / Tampering | transitive dependency tree | medium | mitigate | `npm audit --audit-level=high` surfaces high/critical advisories on every CI run (advisory, non-blocking) (DEPS-03) |
| T-12-06 | Information Disclosure | GitHub Packages publish token | medium | mitigate | Publish auth stays in release.yml via the built-in `GITHUB_TOKEN`; setup-node writes the runtime `.npmrc`; no token committed; write scopes unchanged (D-08) |
| T-12-01 | Tampering | `changesets/action` SHA-pin (release.yml) | high | mitigate | The full-SHA pin + version comment and the auth wiring stay exactly as-is; only checkout/setup-node tags change (D-08) |
| T-12-SC | Tampering | `actions/checkout`, `actions/setup-node` @v5 | low | accept | First-party GitHub-owned actions on a floating major tag; no new third-party action added; runner is GitHub-hosted ubuntu-latest (node24 supported — RESEARCH Pitfall #2). Zero package installs this phase. |
</threat_model>
