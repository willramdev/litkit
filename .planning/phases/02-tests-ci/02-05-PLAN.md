## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted PR code → CI runner | pull_request from a contributor executes install/build/test in the runner |
| GITHUB_TOKEN → repo | the workflow's default token has repository scope |
| third-party GitHub Actions → runner | actions/checkout + actions/setup-node execute in the job |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-11 | Elevation | over-privileged CI token | high | mitigate | Top-level `permissions: contents: read` only; no write scopes, no registry-auth credential, no publish step (publish auth is Phase-4 release.yml) |
| T-02-12 | Tampering | untrusted PR code executing in CI | high | mitigate | Use the standard `pull_request` trigger (not the fork-privileged target trigger); default read-only token; no secrets exposed to fork PRs |
| T-02-13 | Tampering | unpinned third-party actions | medium | mitigate | Pin actions/checkout + actions/setup-node to `@v4` (SHA-pinning of changesets/action is Phase-4 RLS-05) |
| T-02-14 | Information Disclosure | script injection via PR title/branch into run steps | medium | mitigate | Prohibition: do not interpolate untrusted pull-request event fields into run-step shell commands |

No high-severity threat is left unmitigated (ASVS L1, block_on: high).
